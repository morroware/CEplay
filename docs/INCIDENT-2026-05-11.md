# Pause-Groups FCOS Server — Incident & Hardening Notes

**Date:** 2026-05-11
**Host:** webserver (192.168.1.11) — Fedora CoreOS 43.20260413.3.2
**Total downtime:** ~1 hour from first failure to verified-running post-reboot.

---

## What happened

Both Grafana and the pause-groups web app stopped serving requests. Initial symptom on login: `Failed Units: 3` for `nginx.service`, `nginx-letsencrypt-reload.service`, `pause-groups-watchdog.service`.

### Root cause

`/dev/sda4` (the 8 GB root partition that holds `/var/lib/containers`) was at 98% full. Podman's overlay storage had accumulated to ~14 GB of layer data, and Podman's internal bookkeeping SQLite at `/var/lib/containers/storage/db.sql` got corrupted by failed writes once the disk filled. That cascaded into "unable to open database file" and "no space left on device" errors on every `podman` invocation — so systemd couldn't (re)start any container service.

Meanwhile `/dev/sdb1` mounted at `/var/persist` had 118 GB free and was barely used. The storage layer was misallocated, not under-provisioned.

---

## Changes made on this server (in order)

### 1. Podman state was nuked to recover

```bash
sudo podman system prune -af --volumes        # partial — DB was corrupt
sudo podman system reset --force              # full wipe of all Podman state
```

This destroyed all images, containers, and **named volumes** on the host. Bind-mounted data on `/var/persist` was untouched (Grafana data at `/var/persist/grafana`, pause-groups data at `/var/persist/pause-groups/data`, Nginx config at `/var/persist/nginx.conf`, letsencrypt certs at `/var/persist/letsencrypt`).

### 2. Podman storage relocated to the persistent disk

Created `/etc/containers/storage.conf`:

```toml
[storage]
driver = "overlay"
graphroot = "/var/persist/containers/storage"
runroot = "/run/containers/storage"
```

Verify with: `sudo podman info | grep graphRoot`

### 3. SELinux: layered the missing tooling and added a persistent fcontext rule

`semanage` is **not** in the default FCOS image and is required to label the relocated container storage correctly. Without it, `restorecon` mislabels everything `var_t` instead of `container_*_t` and containers fail to load their own shared libraries with errors like `error while loading shared libraries: ... Permission denied` or `RELRO protection failed: No such file or directory`.

```bash
sudo rpm-ostree install policycoreutils-python-utils
sudo systemctl reboot
# after reboot:
sudo semanage fcontext -a -e /var/lib/containers /var/persist/containers
sudo restorecon -Rv /var/persist/containers
```

The `-e` is an **equivalency rule** — it tells SELinux that `/var/persist/containers` should be labeled exactly like `/var/lib/containers`. This is persistent across reboots and survives system-wide relabels (`touch /.autorelabel + reboot`). A `chcon`-only approach does **not** survive a relabel.

### 4. Re-pulled images and brought services back

Quadlets at `/etc/containers/systemd/` (`grafana.container`, `nginx.container`, `tailscale.container`, `certbot.container`, `web.network`) all use `Pull=always` so they auto-pulled on first start.

```bash
sudo systemctl restart web-network.service     # re-create the systemd-web Podman network
sudo systemctl start pause-groups-fpm.service grafana.service nginx.service
sudo systemctl start pause-groups-watchdog.timer
```

### 5. Disk-fill prevention

**Journal cap** (was using 797 MB, capped at 200 MB):

```
/etc/systemd/journald.conf.d/size.conf:
  [Journal]
  SystemMaxUse=200M
  MaxRetentionSec=2week
```

**Weekly Podman prune** (auto-removes unused images older than 7 days):

```
/etc/systemd/system/podman-prune.service  (oneshot: podman system prune -af --filter "until=168h")
/etc/systemd/system/podman-prune.timer    (OnCalendar=weekly, Persistent=true)
```

`sudo systemctl enable --now podman-prune.timer`

## Recovery procedure if this happens again

**Symptom:** `podman` commands return `unable to open database file` or `no space left on device`.

1. **Check disk first** — `df -h`. Look for any partition >90%.
2. **Free space** — if it's the journal: `sudo journalctl --vacuum-size=200M`. If it's container layers and prune fails: `sudo podman system reset --force` (nukes images/containers; bind-mounted data is safe).
3. **Re-pull is automatic** for all Quadlet-managed services (`Pull=always`).
4. **If SELinux labels get broken** (after a relabel event): `sudo restorecon -Rv /var/persist/containers` — the equivalency rule will apply the correct contexts.
5. **`web-network.service` is one-shot.** If reset wiped the `systemd-web` Podman network, restart it explicitly: `sudo systemctl restart web-network.service` (otherwise dependent containers fail with `network not found`).
